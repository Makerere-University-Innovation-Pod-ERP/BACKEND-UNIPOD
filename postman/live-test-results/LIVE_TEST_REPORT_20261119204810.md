## Key findings (all fixed)

1. **Authorization qualifiers.** `x-required-roles` is a role gate, not the complete access rule. Writes in the equipment, stock, lab/textile booking, bootcamp and media areas also require the coordinator to belong to the relevant department; draft edits and submitter replies require ownership. These qualifiers were missing from seven operation descriptions and the shared `Forbidden` response; they are now documented, and the harness models them, so the earlier 22 'anomalies' were false positives.
2. **`respondToSubmissionInfoRequest` (415).** The multipart schema now requires at least one of `note`/`files`/`file` via `anyOf`, `415` is documented with a reusable response, and the global 415 handler now names the media types the endpoint actually accepts instead of always saying 'Use application/json'. A regression test covers the new message.
3. **`registerBrowserPushSubscription` (503).** Expected when VAPID is unconfigured. The operation description now states this and names `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` and `VAPID_SUBJECT` as the three settings that enable it.

## Method

Each operation was driven with valid fixture state against the live Render deployment. A 2xx was required for an `OK` verdict; responses were checked for documented status codes, content type, JSON shape, absence of 5xx/stack traces/secrets. Authorization was checked with an administrator, an allowed non-admin role, a forbidden role and an anonymous caller. Negative checks covered missing authentication, invalid IDs, validation, conflicts and unknown resources.
